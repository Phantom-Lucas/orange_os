# 环境搭建与复现指南

## 1. 已验证环境

| 项目 | 已验证值 |
|---|---|
| 宿主系统 | Ubuntu 22.04.5 LTS x86-64 |
| 内核 | Linux 6.8.0-136-generic |
| 虚拟机 | QEMU `qemu-system-x86_64` |
| 编译链 | GCC、GNU binutils、NASM、GNU Make |
| Guest CPU | 1 vCPU（项目为单核设计） |
| 默认 Guest 内存 | 1 GiB；展示镜像 512 MiB |

版本号以 `tests/collect_env.sh` 在最终机器生成的记录为准。项目未声称在 macOS、Windows
原生环境、ARM 或真机上通过。

## 2. 安装依赖

Ubuntu 22.04 可执行：

```bash
sudo apt update
sudo apt install build-essential binutils nasm make qemu-system-x86 coreutils git
```

构建不需要宿主 libc 链接到 Guest 内核或用户程序；用户 ELF 使用 freestanding/nostdlib
选项。若只查看源码无需安装 QEMU，但所有运行证据都需要它。

## 3. 获取源码与固定版本

```bash
git clone https://github.com/Phantom-Lucas/orange_os.git
cd orange_os
git checkout '[最终答辩 tag 或 commit]'
git status --short --branch
```

最终提交必须把占位符换成真实 tag/commit。若 `git status --short` 不为空，应说明这些改动
是否属于提交内容；不要用未提交工作区生成报告却把主分支链接交给老师。

## 4. 构建

```bash
make build
make check
```

主要制品：

```text
build/mbr.bin
build/loader.bin
build/kernel/kernel.elf
build/kernel/kernel.bin
build/*.elf
build/fs.img
build/images/orange-dev.img
```

`make check` 会验证 MBR 大小/签名、Loader 大小、内核磁盘容量、含 BSS 的物理边界、
用户 ELF 和 MyFS 制品。当前基线中的 `kernel.bin` 为 93,388 B；这个数字不是硬编码限制，
未来构建可能变化，应以检查结果为准。

## 5. 首次创建磁盘与运行

```bash
make bootstrap
make run
```

`bootstrap` 会把 MBR、Loader、内核和全新 MyFS 写入开发盘。注意：`format-fs` 和
`bootstrap` 会覆盖目标磁盘的 MyFS 区域，已有 Guest 文件会丢失。日常改内核而希望保留
文件时，直接 `make run`；它只执行 `install-kernel`。

图形终端是默认后端。文本回退可用：

```bash
make CONSOLE_BACKEND=vga run
```

支持的 framebuffer 模式：

```bash
make FB_MODE=1024x768 run
make FB_MODE=1280x720 run
make FB_MODE=1440x900 run
```

## 6. 独立答辩镜像

答辩前只需准备一次：

```bash
make fb-showcase-prepare
```

之后启动都使用：

```bash
make fb-showcase
```

不要在展示 proof 文件持久化之前再次执行 `fb-showcase-prepare`，因为它会格式化独立演示盘。
展示镜像路径默认为 `build/images/orange-showcase.img`，不会污染开发盘。

## 7. 测试

```bash
make test-list
make test-self
make test-fast
make test PROFILE=full SEED=20260821 KEEP_FAILED=1
make test CASE=sync.stress SEED=20260821 KEEP_FAILED=1
```

- fast：构建与 mkfs 快速门。
- full：fast + 15 个有界功能/集成用例。
- stress：full 的超集，并加入耗时压力用例；可直接 `make test-stress`。
- `KEEP_FAILED=1`：失败时保留工作目录，便于复盘。

测试会创建独立临时镜像。不要让已有交互式 QEMU 长时间占用同一宿主资源；同步压力对宿主
调度敏感。失败结果在 `build/test-artifacts/` 下保存日志、环境、命令、结果和截图。

## 8. 调试

```bash
make debug
```

QEMU 会以 `-S -s` 暂停并监听 TCP 1234。另一个终端可执行：

```bash
gdb build/kernel/kernel.elf
(gdb) target remote :1234
(gdb) break kernel_main
(gdb) continue
```

若调试启动阶段，可打开详细 Guest 日志：

```bash
make BOOT_DIAGNOSTIC=1 run
```

## 9. 常见环境问题

| 现象 | 处理 |
|---|---|
| `qemu-system-x86_64: command not found` | 安装 `qemu-system-x86` |
| monitor socket `Operation not permitted` | 换到允许 Unix socket 的本地目录/环境后重跑 |
| 同步测试异常变慢 | 检查并关闭无关 QEMU，保留 seed，重跑相同 case |
| 演示文件消失 | 检查是否误执行 `*-showcase-prepare` 或 `format-fs` |
| 内核超出磁盘/物理上界 | 读取 Makefile 的明确错误，减小内核或重新设计启动布局，不能删检查 |
| 图形终端空白 | 用 `CONSOLE_BACKEND=vga` 区分 framebuffer 问题和内核启动问题 |
