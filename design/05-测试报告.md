# Orange/64 测试报告

## 1. 测试目标

测试不是对单个 C 函数做形式化证明，而是从构建制品、QEMU 黑盒交互、Guest 自检和磁盘
重启四个角度验证系统闭环。重点覆盖容易“看似能跑、边界即坏”的路径：内核增长、用户态
异常、COW、同步竞争、文件持久化、LBA48、键盘连发和显示像素。

## 2. 测试框架

`tests/manifest.sh` 注册 suite、case、profile、超时和函数。公共 runner 为每次运行生成固定
seed、独立 work 目录和 artifact，使用 QEMU monitor 发送按键/读取 VGA/截图，并把结果
分成 `PASS`、`FAIL`、`TIMEOUT`、`ERROR` 和 `INFRASTRUCTURE_ERROR`。

profile 的包含关系：

```text
fast   = 快速构建门
full   = fast + 有界功能/集成回归
stress = full + 长时间压力用例
```

## 4. 同步压力测试

执行命令：

```bash
make test CASE=sync.stress SEED=20260821 KEEP_FAILED=1
```

配置：100 轮 × 4 个用户线程 × 每线程 20,000 次共享计数更新，case 超时 1800 秒。  
artifact：`build/baseline/2026-08/final-stress-fixed/20260821-013853-204963-20260821/`

结果：PASS，QEMU exit code 0。该结果用于补充 full 中 10 轮确定性门，不用低轮次替代压力
结论。压力耗时受宿主 CPU 与其他 QEMU 进程影响，因此必须记录环境与 seed。

## 6. 发现过的失败及其性质

测试过程曾出现以下失败，均未从记录中删除：

- monitor socket `Operation not permitted`：沙箱基础设施限制，分类为 infrastructure，不是内核
  PASS/FAIL。
- 快速 HMP 输入出现 `scroll-fter`：真实输入丢字，促成键盘 IRQ 排空修复。
- 100 轮同步在 900 秒超时：宿主负载敏感，促成 full/stress 拆分和 1800 秒独立门。
- 两个遗留 QEMU 同时运行导致 10 轮同步超时：关闭遗留进程后同 seed 通过，说明测试前需
  固定宿主环境。
- `sync.stress` 初次报 127：runner 子 shell 没有导出 wrapper 依赖函数，修复为导出完整
  manifest 函数集合。

记录这些过程比只写“全部通过”更能说明测试确实参与了设计反馈。

## 7. 结果边界

- 通过 QEMU 不等于真机兼容；未做真机测试。
- 单核测试不证明 SMP 正确性；系统明确配置 `-smp 1`。
- 100 轮压力提高置信度，不构成无竞争错误的数学证明。
- 稀疏 256 GiB 镜像验证寻址边界，不代表真实写满 256 GiB 的吞吐与耐久。
- 当前报告对应工作区；最终提交必须从干净 tag 重跑并更新 artifact/commit。
