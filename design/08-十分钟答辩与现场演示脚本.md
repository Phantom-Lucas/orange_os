# 十分钟答辩与现场演示脚本

## 1. 总体节奏

目标是 10 分钟内完成“问题—设计—证据—边界”闭环，其中 PPT 约 6 分 30 秒，现场演示
约 3 分 30 秒。不要逐目录念功能，也不要在现场编译或跑完整测试。

| 时间 | 页/动作 | 核心句 |
|---|---|---|
| 0:00–0:25 | P1 封面 | 我实现了一个从 MBR 到 Ring 3 应用的 x86-64 教学操作系统 |
| 0:25–0:55 | P2 目标与结果 | 自举、隔离、持久化、交互、验证五个闭环 |
| 0:55–1:35 | P3 架构 | 沿启动链自上而下讲，不逐文件罗列 |
| 1:35–2:10 | P4 Orange'S 对照 | 继承路线，升级 64 位、VM、Shell、测试 |
| 2:10–2:45 | P5 Loader | 精确扇区、255 分块、磁盘/物理双边界 |
| 2:45–3:20 | P6 进程与 VM | 独立 CR3、fork、COW、mmap、fault isolation |
| 3:20–3:50 | P7 IPC/FS/TTY | 用三条数据流说明跨模块协作 |
| 3:50–4:10 | P8 演示路线 | 预告六步 guided tour 与判定标准 |
| 4:10–7:40 | 切 QEMU 现场演示 | `about`、`ps`、`demo`、proof、控制台 |
| 7:40–8:20 | P9 测试证据 | full 16/16 + stress 100×20,000 |
| 8:20–8:55 | P10 关键问题 | 固定 Loader、BSS、键盘漏字、测试分层 |
| 8:55–9:25 | P11 个人贡献与来源 | 真实说明本人工作、参考和 AI 辅助边界 |
| 9:25–10:00 | P12 总结与限制 | 达成什么、没做什么、下一步是什么 |

## 2. 演示前准备

至少提前一天：

```bash
git checkout '[最终答辩 tag]'
make check
make test CASE=showcase.core SEED=20260821 KEEP_FAILED=1
make fb-showcase-prepare
make fb-showcase
```

进入系统先手工运行一次：

```text
demo
cat demo-proof.txt
```

退出 QEMU，再用 `make fb-showcase` 重开并确认 proof 仍在。演示当天不要再次运行
`fb-showcase-prepare`，避免重新格式化。

现场准备：

- QEMU 已启动并停在 prompt；PPT 和 QEMU 用 Alt+Tab 切换。
- 终端字号、投影分辨率和键盘布局提前确认。
- 关闭无关 QEMU、升级弹窗、即时通信和省电锁屏。
- 把最终测试截图和日志页离线放在 PPT，不能依赖网络。
- Guest 只输入 ASCII；系统没有 Unicode/CJK 输入支持。

## 3. PPT 口播稿

### 0:00–0:25 封面

“老师好，我的项目是 Orange/64。它参考 Orange'S 从引导扇区逐步构建操作系统的路线，
但实现目标是 x86-64：从自己的 MBR 和 Loader 启动，进入高半区内核，再运行 Ring 3 的
Shell 和用户程序。下面我重点讲四条核心链并现场验证。”

### 0:25–0:55 目标与结果

“项目不是只追求启动画面，而是五个闭环：裸机自举、用户隔离、磁盘持久化、Shell 交互、
自动验证。目前有 36 个系统调用、20 余个用户程序，固定种子完整回归 16 项全部通过，另有
100 轮同步压力测试。”

### 0:55–1:35 架构

“BIOS 先加载 MBR，二级 Loader 读内核、建立页表并进入长模式。内核内部由中断、内存、
进程线程、IPC、ATA/MyFS 和 TTY 组成；系统调用向 Ring 3 暴露接口，用户态 libc 支撑 Shell
和程序。进程保存地址空间与文件表，线程保存调度现场；FS 和 TTY 请求与 IRQ/用户缓冲解耦。”

### 1:35–2:10 对照

“我继承的是 Orange'S 的实现顺序和操作系统构件，不是逐行复制 32 位代码。对应增量包括
64 位 `SYSCALL/SYSRET`、每进程 CR3、COW 与 mmap、LBA48、层级 MyFS、framebuffer、
管道重定向和自动化测试。没有实现网络、SMP 和完整 POSIX，这些在最后明确列为边界。”

### 2:10–2:45 Loader

“这个模块体现了从能跑到可增长。旧设计固定读内核尾部，代码变大后会静默截断。现在 Make
计算实际扇区并注入 Loader，超过 ATA 单命令 255 扇区就分块；构建同时检查不能碰 MyFS 和
0x70000 启动页表。专项测试把内核填充到 300 扇区，仍能进入 Ring 3 Shell。”

### 2:45–3:20 VM

“每个进程有独立页表。fork 后父子可写私有页变成只读 COW，引用计数增加；首次写触发页
错误，必要时复制后恢复写权限。匿名 mmap 用 VMA 描述并立即分配，ELF 栈可在 8 MiB VMA
内按缺页向下增长。用户程序崩溃只结束该
进程，不让内核 panic。演示会直接看到父 1111、子 2222、父仍 1111。”

### 3:20–3:50 IPC/FS/TTY

“消息 IPC 和 futex 连接用户同步与调度；MyFS 由 LBA48 驱动支撑，使用动态超级块布局和
三级间接索引；TTY 把键盘 IRQ、三个控制台和 Shell 前台任务串起来。Shell 的管道和重定向
复用 fork、exec、pipe、dup2，而不是专用展示接口。”

### 3:50–4:10 演示预告

“下面运行用户态 `demo`。它只通过公开系统调用验证系统观察、COW、IPC、线程、文件系统和
故障隔离，每一步打印输入、实际值和预期值，目标是 6 passed 0 failed。”

## 4. 现场演示操作

### 4:10–4:35 系统身份

切换到已启动的 QEMU：

```text
about
ps
```

指向 `ps` 的 PID、PPID、STATE、THREADS 和 USERPAGES：“这是 Ring 3 Shell 通过 `ps`
系统调用获取的快照。”不要逐行念输出。

### 4:35–6:55 六步 guided tour

```text
demo
```

程序运行时只解释四个固定点：

- COW：`0x1111 / 0x2222 / 0x1111`。
- IPC：父子往返 `0xC0DE`。
- THREADS：4 个 TID、counter=4、join 退出码。
- FAULT：子进程 fault，showcase 继续并最终 `RESULT 6 passed 0 failed`。

不要等每一行才解释；输出滚动时先让程序跑完，再用 PageUp 查看遗漏。

### 6:55–7:20 持久化

```text
cat demo-proof.txt
```

“这个文件由上一次准备阶段的 demo 写入，QEMU 退出并重新启动后仍在；自动测试还会执行
创建、重开、stat 和二次启动检查。”现场不再重启，以节省时间。

### 7:20–7:40 控制台

按 F2，再按 F1 返回。说明每个控制台有独立缓冲与历史；默认显示是 framebuffer，VGA 文本
后端作为回退和测试 oracle。立刻切回 PPT。

## 5. 收尾口播

### 7:40–8:20 测试

“测试以固定 seed 和临时磁盘运行，16 项 full 覆盖动态 Loader、LBA48、FS、TTY、用户态、
同步、COW、集成、showcase、framebuffer 和 Shell 编辑；全部 PASS。100 轮同步是独立 stress
门，避免把宿主负载超时和功能失败混为一谈。”

### 8:20–8:55 关键问题

“四个代表问题分别是内核增长导致截断、BSS 不应依赖磁盘零填充、8042 扫描码积压导致漏字，
以及长压力测试需要和发布门分层。每个问题都形成了代码修复和专门回归。”

### 8:55–9:25 贡献与来源

这里必须用本人真实内容替换：

“本项目是单人组。我负责 `[真实模块]` 的设计/实现/重写，以及系统集成、调试、测试和答辩。
我参考 Orange'S 与公开资料，并使用 AI 做 `[真实用途]`。具体来源已逐模块列入报告；我不把
参考或 AI 生成内容描述为纯手写，所认领核心模块都能现场解释。”

### 9:25–10:00 总结

“项目完成了从 MBR、64 位内核到 Ring 3 应用的闭环，重点增量是隔离、COW/同步、持久化
存储、交互 Shell 和可重复测试。当前边界是单核、QEMU、无网络、无日志 FS、无完整 POSIX。
如果继续开发，我会优先做文件系统崩溃一致性和页缓存，而不是继续堆界面功能。谢谢老师。”

## 6. 故障预案

| 故障 | 当场处理 |
|---|---|
| QEMU 未响应 | 等 5 秒；仍无响应切回 PPT 的自动测试截图，不现场重编译 |
| `demo` 某步 FAIL | 保留画面，说明实际/预期会写入 artifact；切测试证据，不伪称成功 |
| 键盘输入错误 | Ctrl+U 清行后只重输一次；仍失败切截图 |
| 画面太小 | 使用准备好的终端截图；不要现场改分辨率重启 |
| proof 不存在 | 不临时伪造，展示 `showcase.core` 的重启日志并说明准备盘被重置 |
| 时间只剩 1 分钟 | 跳过 P10/P11 细节，直接讲真实贡献一句和 P12 结论 |

## 7. 三次彩排标准

- 第一次：允许看稿，记录每段实际耗时。
- 第二次：只看 PPT 关键词，演示命令零失误，控制在 9:20～9:40。
- 第三次：模拟投影和老师打断，回答一个问题后仍在 10 分钟内收尾。
