# 答辩问题库

回答原则：先说结论，再说关键不变量，最后给源码/测试证据。每题控制在 20～40 秒；不知道
的边界直接说明未实现或需查证，不猜测。

## 启动与体系结构

### 1. 为什么不用 GRUB？

课程目标包含引导程序。自写 MBR/Loader 能完整展示磁盘读取、A20、页表和长模式切换；代价是
需要自己维护内核加载和物理布局边界。

### 2. 为什么需要二级 Loader？

MBR 只有 512 B，还要包含 `0x55AA` 签名，无法容纳 E820、长模式页表和大内核
加载逻辑，所以第一阶段只负责读取第二阶段。

### 3. 188 扇区问题如何修复？

Make 根据 `kernel.bin` 实际大小计算扇区并传给 NASM；Loader 把超过预加载部分按 ATA 单次
最多 255 扇区分块读取。构建还检查内核不能碰 MyFS 和 0x70000 页表。

### 4. 为什么还要检查 `.bss`，kernel.bin 大小不够吗？

不够。原始镜像可能不存储 BSS 的零字节，但运行时必须为它保留并清零内存；因此物理上界要
看链接符号 `__kernel_phys_end`，入口按 `__bss_start/end` 清零。

### 5. 为什么用高半区内核？

把内核虚拟地址与用户低地址空间分离，所有进程可共享内核映射，同时每进程拥有自己的用户
映射，便于权限和地址空间管理。

## 特权级与系统调用

### 6. Ring 3 如何进入内核？

用户包装器执行 `syscall`；CPU 从 MSR 取得内核入口，入口 `swapgs`、切内核栈、保存用户
RIP/RFLAGS/RSP 和参数，C 分发完成后用 `sysret` 返回。

### 7. 为什么不能直接解引用用户指针？

用户可传未映射、只读、跨边界或内核地址。系统调用先检查范围并 copyin/copyout，阻塞服务
也使用内核暂存区，避免调度后继续持有不稳定用户地址。

### 8. 用户程序 page fault 为什么不让内核崩溃？

异常处理检查 fault 来源和当前进程。可处理的 COW 或合法向下增长栈页先修复；非法用户访问转为该进程
退出状态，只有内核态不可恢复错误才 panic。

## 进程、线程与内存

### 9. 进程和线程有什么区别？

进程拥有 CR3、文件表、cwd、VMA 和父子关系；同进程线程共享这些资源，但各自拥有调度现场、
内核栈、用户栈、TLS、TID 和阻塞状态。

### 10. `fork` 怎样实现？

复制进程元数据、文件对象引用和用户页表；私有可写页在父子页表中改成 COW 只读并增加物理
页引用，复制 syscall 返回现场，使父返回子 PID、子返回 0。

### 11. COW fault 怎样处理？

确认是用户写、PTE 带 COW。引用数大于 1 时分配新页并复制，减少旧页引用；等于 1 时可直接
恢复写权限。两种都清 COW 并刷新对应 TLB。

### 12. `mmap` 是否完整兼容 Linux？

否。当前主要支持匿名私有映射、调用时页面分配和 munmap；ELF 栈另有按缺页增长。没有完整
文件映射、共享映射、swap
或 Linux 全部 flags。

### 13. 调度是怎样的？

单核抢占式调度，时钟中断提供时间片；阻塞的 IPC、wait、futex 和 I/O 请求让出 CPU，事件
发生后进入可运行队列。项目未实现 SMP。

### 14. 为什么同步压力要 100 轮？

竞争 bug 有时不会在一次调度交错中出现。100 轮提高覆盖不同交错的概率；它不构成形式化
证明，所以另有确定性不变量和功能断言。

### 15. futex 的思想是什么？

无竞争时用户态原子操作完成，不进入内核；需要等待/唤醒时才调用内核。wait 必须把值检查与
入等待队列放在正确锁保护下，避免 lost wakeup。

## IPC、文件系统与 Shell

### 16. IPC 与共享内存有什么区别？

当前消息 IPC 按 PID 发送结构化小消息，内核管理阻塞/唤醒和来源；同进程线程天然共享地址
空间并用 futex 同步。跨进程通用共享内存尚未作为独立接口实现。

### 17. 为什么 FS 用服务线程？

把系统调用用户复制与磁盘/文件系统操作解耦，统一串行化请求并保持锁/睡眠边界清晰。它受
Orange'S 服务化思路启发，但仍运行在同一个内核地址空间，不是强隔离微内核服务器。

### 18. MyFS 的文件如何扩大？

inode 有 11 个直接块，随后依次使用一级、二级、三级间接表。分配时更新数据位图和索引块，
读写按文件块号解析相应层级。

### 19. 如何证明文件真的持久化？

showcase 创建并重开 `demo-proof.txt`，校验内容和 stat；自动用例退出 QEMU、用同一磁盘再次
启动后重新读取。跨进程不够，必须跨 Guest 重启。

### 20. LBA48 测试为什么用 256 GiB 稀疏镜像？

LBA28 的 512 B 扇区边界约 128 GiB。把 MyFS 放到该边界以上即可证明命令与地址没有被截为
28 位；稀疏文件避免真实占用 256 GiB 宿主磁盘。

### 21. 管道如何实现？

Shell 创建 pipe，fork 子进程，用 dup2 把 stdout/stdin 接到管道端，关闭多余 FD，再 exec；
内核 file object 维护端点和引用，read/write 根据数据/端点状态阻塞或结束。

### 22. 后台任务是否等于 POSIX job control？

不等于。当前 `&` 允许 Shell 不同步等待并可用 ps/kill 管理，TTY 有前台 PID；没有完整进程组、
session、`tcsetpgrp`、SIGTSTP/fg/bg 语义。

## 设备、显示与测试

### 23. 键盘漏字的根因和修复是什么？

渲染/系统调用繁忙时 8042 输出缓冲可能积累多个扫描码，旧 ISR 一次只读一个就确认 PIC。
当前每次 IRQ 排空待处理字节（上限 64），并用快速输入重复测试验证。

### 24. framebuffer 和 VGA 是什么关系？

默认交互由内核扫描 QEMU/Bochs VGA 的 PCI BAR、设置 Bochs 显示寄存器并映射线性
framebuffer，随后用 PSF 字体绘制；VGA 文本模式是低复杂度回退，也是多数自动测试读取
80×25 文本的 oracle。framebuffer 有独立像素截图测试。

### 25. 测试如何判断不是只打印了 PASS？

不同 case 从外部操作磁盘和 QEMU monitor，检查重启前后文件、图像尺寸/像素、输入结果、
进程退出与构建边界。showcase 的 PASS 只是其中一层，不能替代独立 FS/VM/LBA48 用例。

### 26. 为什么固定 seed？

便于失败后重放相同测试数据/节奏并对比修改。固定 seed 不代表调度完全确定，所以仍需重复和
压力门。

### 27. TIMEOUT 是否等于内核 bug？

不必然。先区分 Guest 无进展、宿主资源竞争和 monitor 基础设施。相同环境/seed 复现后再定性；
但超时也绝不能写成 PASS。

## 项目范围与贡献

### 28. 这个项目算微内核吗？

不算严格微内核。FS/TTY 有服务线程和消息式组织，但驱动、文件系统和服务仍在内核地址空间，
没有用户态服务器隔离。更准确的说法是单体内核中的服务化结构。

### 29. 最大的局限是什么？

单核和 QEMU 硬件假设限制最明显；文件系统没有日志/权限，VM 无 file-backed mmap/swap，
Shell 非完整 POSIX。报告主动把这些列为边界。

公开资料和 AI 分别用于什么。不要用含糊的“AI 只辅助”或无证据百分比回答。

### 31. 代码量达到 50% 吗？

统计；若尚未完成核对，应在答辩前完成。工程总行数不能直接证明手写比例。

更多 UI 命令更能提升操作系统核心完整性。
